# Hand Tracking project

MediaPipe 손 제스처 인식 및 랜드마크 녹화 프로젝트입니다.

```text
main.py                 카메라 및 녹화 상태 흐름, 실행 진입점
config.py               경로, 카메라, 화면, 제스처 임계값 설정
models/
  gesture_recognizer.task
  hand_landmarker.task
  llm_chat.py           Ollama 클라이언트
  interpretation.py     인식된 제스처의 LLM 프롬프트
common/
  camera.py             카메라 설정 및 실제 입력 해상도 확인
  filters.py            좌표 평활화 필터
  geometry.py           거리 및 손가락 간격 계산
  drawing.py            손 랜드마크 화면 표시
  recording.py          JSONL 스트리밍 저장 및 JSON/JSONL 읽기
gestures/
  detectors.py          OK, 말하는 손, MediaPipe 카테고리 판정
  asl_alphabet.py       ASL 수동 자모의 기하 기준선
research/
  asl-fingerspelling/   핑거스펠링 구현에 쓴 논문과 데이터 출처
recordings/             로컬 녹화 데이터
tests/                  녹화 저장 및 자모 판정 검증
```

`opencv-python`, `mediapipe`, `numpy`가 설치된 Python 환경에서 실행합니다.

```sh
python main.py
```

카메라 번호는 `config.py`의 `CAMERA_INDEX`에서 변경합니다. 현재 카메라 백엔드는 macOS의 AVFoundation을 사용합니다. LLM 클라이언트는 기본적으로 로컬 Ollama의 `qwen3.5:2b`를 사용하지만, 현재 녹화 흐름에서는 ASL 의미 라벨을 학습하기 전까지 LLM을 호출하지 않습니다.

기본 설정은 내장 FaceTime 카메라(`CAMERA_INDEX = 0`)와 `1920×1080`입니다. 이전에 조회한 아이폰 카메라는 `1920×1440`을 지원했지만, 연결 상태에 따라 번호가 바뀌거나 열리지 않을 수 있습니다. 시작 시 실제 수신 프레임의 해상도를 출력하며 요청값과 다르면 경고합니다. 화면에도 실제 해상도와 처리 FPS를 표시합니다.

기본 표시는 일반 창이며 `F`로 전체 화면을 전환합니다. 원본 프레임을 OpenCV 창으로 직접 전달해 기존 `960×720` 강제 축소를 제거했으며, 창 크기에 맞춰 종횡비를 유지해 표시합니다. `DISPLAY_SIZE`는 일반 창의 초기 크기이며 촬영 해상도에는 영향을 주지 않습니다. 고해상도에서는 처리 FPS가 낮아질 수 있습니다.

- 시작: 말하는 손 제스처 3회
- 완료: OK 1초 유지
- 취소: 주먹 2초 유지
- 녹화 중 화면의 `ASL`은 현재 손 모양의 알파벳 후보이다. 한 글자를 약 0.32초 유지하면 철자 문자열에 들어간다. J와 Z는 같은 손 모양이 이어지는 동안의 손가락 궤적으로 구분한다.
- 완료 시점의 OK는 알파벳 F와 같은 손 모양이므로, 마지막 1초는 철자에서 뺀다. 주먹을 2초 유지하면 녹화가 취소되어 철자는 저장되지 않는다.
- `F`: 전체 화면 전환, `N`: 완료 후 새 녹화 대기, `S`: 평활화 전환, `R`: 추적 초기화, `Q`/ESC: 종료

## 녹화 형식

새 녹화는 세션마다 하나의 JSONL 파일로 저장합니다. 각 줄은 독립적인 JSON 객체입니다.

1. `session`: 형식 버전(`gesture-landmarks-v3`), 의미 및 라벨 상태
2. `frame`: 프레임별 시간 `t`와 양손의 정규화된 `[x, y, z]` 랜드마크
3. `event`: 완료 시 기록하는 인식 제스처 구간
4. `summary`: 완료 시 기록하는 전체 녹화 시간과, 완료된 경우의 `fingerspelling` 가설 (`text`, `letters`, `method`)

프레임마다 디스크에 기록하므로 녹화 길이에 비례해 프레임 목록을 메모리에 쌓지 않습니다. JSONL은 한 줄씩 읽을 수 있고, 들여쓰기를 제거해 기존 JSON보다 저장량도 줄어듭니다. 압축 형식은 아니므로 데이터가 더 커지면 완료된 파일의 gzip 압축이나 학습용 Parquet 변환을 별도로 고려할 수 있습니다.

녹화 중에는 `.jsonl.partial` 확장자를 사용하며 완료하면 `.jsonl`로 변경합니다. 취소 시 해당 임시 파일을 삭제합니다. 녹화 도중 종료하거나 오류가 나면 미완료 파일을 남기며, 학습 데이터로 사용할 때는 완료된 `.json`/`.jsonl`만 선택해야 합니다. 프레임은 매번 flush하지만 정전까지 견디는 디스크 동기화를 보장하지는 않습니다.

기존 JSON 샘플은 그대로 보존합니다. `common.recording.load_session(path)`는 기존 JSON과 새 JSONL을 동일한 payload 구조로 읽습니다. 대용량 JSONL 처리 시에는 전체 파일을 메모리에 적재하는 `load_session` 대신 `iter_session_records(path)`로 순회합니다.

새 녹화 파일은 `.gitignore`로 Git에서 제외합니다. 이미 추적 중인 기존 샘플에는 적용되지 않습니다. 실제 녹화 데이터는 별도 스토리지나 백업으로 관리하세요.

## 검은 화면 또는 카메라 연결 오류

카메라 번호는 현재 장치 목록의 0부터 시작하는 번호입니다. 0·1 두 장치가 있다면 2번은 존재하지 않습니다. 아이폰이 목록에 있어도 연결 상태에 따라 열기에 실패할 수 있습니다.

먼저 모델 없이 원본 카메라 화면만 확인할 수 있습니다.

```sh
python -m common.camera --index 0 --width 1920 --height 1080
```

미리보기는 첫 프레임의 실제 해상도와 평균 픽셀값(0~255)을 출력합니다. 이 값은 원본 프레임이 거의 검은색인지 확인하는 단서이며, 밝기만으로 원인을 확정할 수는 없습니다. 미리보기는 정상인데 `main.py`만 검다면 모델/화면 표시 쪽을 확인하고, 미리보기도 검다면 카메라 가림·연결·다른 앱에서의 작동 상태를 확인하세요. 카메라를 열지 못한다면 macOS 시스템 설정의 개인정보 보호 및 보안 > 카메라에서 실행 터미널/IDE의 권한도 확인하세요.

프레임 수신 실패 시 창 이벤트를 계속 처리하며 `Q`/ESC로 종료할 수 있습니다. 5초 동안 프레임이 없으면 무한 대기 대신 오류를 출력합니다. 카메라 미리보기는 영상을 파일에 저장하지 않습니다.
